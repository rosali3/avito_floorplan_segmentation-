## 1. Постановка задачи

- Train/valid: `combined_out` (ResPlan_v2 + CubiCasa5K), instance-аннотации
  сгенерированы из семантических масок (connected components), свой 80/20
  сплит (seed=42, стратифицирован по источнику).
- Test: `ugc_labeled` (реальные BTI-планы, Roboflow COCO), все три подпапки
  (train/valid/test) объединены в один test-сплит — **~33 картинки**,
  результаты статистически шумные, особенно per-class breakdown.
- Таксономия: 7 классов (`living, bedroom, bathroom, kitchen, balcony, wall,
  opening`), test-категории сведены к ним по `configs/classes.yaml`
  (`restroom->bathroom`, `door/window/enterence->opening`, часть категорий
  исключена как не имеющая соответствия в train-таксономии).

## 5. Методологические оговорки (важно учитывать при интерпретации)

- **SegFormer** — единственная модель без нативных instances; сравнивается
  через постфактум connected-components по предсказанной семантической карте
  (`models/segformer/infer_and_eval.py`). Это структурно невыгодный для неё
  режим сравнения (напр. одна "смазанная" граница между двумя комнатами может
  дать сразу и false positive, и false negative там, где YOLO/RF-DETR/MaskRCNN
  просто предсказывают два чистых инстанса) — сильное отставание SegFormer в
  mask AP не обязательно значит, что семантическая сегментация хуже "по сути",
  это скорее иллюстрация, что semantic-seg архитектура не для этой метрики
  создана.
- **SAM zero-shot / fine-tuned** — полностью automatic pipeline (боксы от
  GroundingDINO по тексту, не GT), сравнимы с остальными моделями "на равных".
  Оба варианта используют ОДИН И ТОТ ЖЕ детектор боксов — разница между ними
  отражает исключительно эффект дообучения mask_decoder.
- **Test-сплит крошечный (~33 картинки).** Разница в 0.02-0.05 mAP между
  моделями может быть шумом, а не реальным различием в качестве — не делай
  сильных выводов без здравого запаса.
- **Классы `bedroom`/`living`** почти наверняка не встречаются (или почти не
  встречаются) в test GT после маппинга ugc-категорий — их AP будет NaN/малым
  числом наблюдений, а не показателем плохого качества модели.

## 6. Выводы: какая модель лучше и почему

[ЗАПОЛНИТЬ на основе фактических цифр — по опыту подобных сравнений держи в
голове типичные компромиссы, чтобы объяснить, ПОЧЕМУ то или иное место в
таблице, а не просто констатировать цифры:]

- RF-DETR-Seg / YOLO-seg / Mask R-CNN — end-to-end обученные детекторы на
  одном и том же train-домене; ожидаемо сильнее на in-domain валидации,
  вопрос именно в generalization на test (другой домен — реальные сканы).
- Mask R-CNN как "классический" бейзлайн обычно даёт крепкий, но не топовый
  результат при разумном компьюте, RF-DETR/YOLO — более новые архитектуры,
  часто выигрывают по скорости сходимости на маленьких датасетах.
- SAM (даже дообученный) ограничен качеством боксов от GroundingDINO — если
  GroundingDINO плохо ищет объекты на чертежах (он обучен на фото, не на
  чертежах), это узкое место всей SAM-ветки независимо от качества самих масок.
