Брифинг для senior DS

Задача и постановка

Сравнительное исследование instance segmentation для floor-plan комнат (living/bedroom/bathroom/kitchen/balcony/wall/opening) — 5 архитектур (RF-DETR-Seg, YOLO11-seg, Mask R-CNN, SegFormer, SAM zero-shot+finetune) на одном train/test сплите, с конечной целью — распознавание планов из реальных объявлений (Avito/Cian), плюс отдельная ветка про furniture-aware пост-хок коррекцию комнат.

Данные и главный методологический риск

Train — синтетика/вектор (ResPlan_v2 + CubiCasa5K, ~20k), test — 33 реальных скана BTI-планов с Avito (UGC). Это не two-similar-domains задача, это честный sim-to-real transfer — и это подтвердилось количественно: валидационный mAP ~0.85-0.90 на синтетике падает до 0.13-0.25 на UGC. Это не баг, это ожидаемый и задокументированный domain gap.

Второй риск, который нужно держать в голове при любой интерпретации цифр: test-сплит — 33 картинки. Все AP/recall числа ниже — направление, не статистически надёжная оценка. Я не считала доверительные интервалы/bootstrap, стоило бы, если исследование пойдёт дальше.

Главная находка — не архитектурная, а data-quality

Собственный connected-components экстрактор инстансов (из семантических масок в instance-разметку — у исходных данных не было native instance labels) содержал баг: bbox считался из аппроксимированного полигона контура, а не из пиксельной маски. Для тонких классов (двери/окна, тонкие стены) это давало bbox меньше реальной площади объекта — геометрически невозможная аннотация. Проверка: 65% всех bbox в train-датасете были "невозможными" (area > bbox_area), у класса opening — 98%. Это портило box-регрессию для всех box-based моделей, не косметическая проблема. Исправлено (bbox теперь строго из pixel mask), плюс добавлено эмпирически провалидированное слияние фрагментов, разрезанных ignore-шумом (dilate_gap_px) — проверила на выборке, что оно режет спурионные разрывы комнат (bedroom -33% инстансов), но почти не трогает wall (реально многосегментный класс, -0.5%) — то есть фикс не переусреднял данные вслепую.

RF-DETR и Mask R-CNN переехали на исправленные данные (data_v2); YOLO осознанно оставлен на старых — по прямому решению (не хотели терять прогресс обучения), это сознательный компромисс, не забывчивость.

Инфраструктура — были реальные потери

- Два shared GPU-сервера (school1/school19), доступ на одном из них отозвэкстренно гасить все процессы. Mask R-CNN потерян полностью — убит насередине 1-й эпохи, mmengine чекпоинтит только по завершении эпохи, ни одного файла весов не осталось. Практический вывод для следующего раза: чаще чекпоинтить/сохранять
mid-epoch state на нестабильной инфраструктуре.
- Зависимости были болезненные и нетривиальные: mmcv/mmdet несовместимы с Python 3.12 (pkgutil.ImpImporter removed) — решено через отдельный venv на Python 3.10; NumPy 2.x ABI
ломает torch/pycocotools сегфолтом, не исключением — нашла через бисекцию под Windows без MSVC — форсирован CPU-fallback для одного кастомногооператора (осознанное снижение скорости инференса SAM ради вообще рабочей установки).

Методологически интересные находки (не просто цифры)

1. Confidence threshold — не тюнинг-мелочь, а сигнал: снижение порога 0.3→0.1 дало реальный прирост mAP на UGC у обеих моделей — модели систематически недоуверены на чужом
домене (классический symptom domain shift, не проблема самих детекций).
2. Настоящая confusion matrix (не per-class AP, а "GT-класс → какой класс предсказан"): RF-DETR путает generic "room" с "kitchen" в 41% случаев, YOLO — почти никогда (склоняется
к living/bedroom, что содержательно правдоподобнее). wall/opening — recalканах при 0.85+ на синтетике, при этом balcony не детектится вообще ниодной моделью.
3. "Мягкий" скоринг как отдельный слой, не замена строгому: явно разделили несовпадении таксономий" (room→living, засчитывается) от "модель реальноошиблась" (room→kitchen, не засчитывается) — важно не смешивать эти два типа ошибок в одну метрику.
4. restroom уже корректно слит с bathroom — не гипотеза, проверено на реа и в confusion-анализе.
