  (ResPlan_v2 + CubiCasa5K, 256x256, 20079 картинок). У папки уже есть свой
  независимый пайплайн (`resplan_dataset.py`, `train_generic.py`, `model.py`,

  аугментациями/лоссом — мы его НЕ трогаем, только читаем/импортируем
  `resplan_dataset.ResPlanSegmentation` для SegFormer (см. ниже).

  аугментаций (WALL_ID/OPENING_IDS от старой 12-классовой таксономии) —
  он одинаково действует на все модели, обученные через
  `resplan_dataset.py` (в нашем исследовании — только SegFormer), поэтому
  сознательно не чинится, чтобы не давать SegFormer нечестное преимущество.
  RF-DETR/YOLO/MaskRCNN/SAM НЕ используют этот аугментатор вообще (свой

  `train_generic.py` напрямую, только класс `ResPlanSegmentation` с
  параметром `ids=` (свой список файлов) — эта ветка кода `val_resplan.txt`
  не трогает вообще. Если пользователь захочет и `train_generic.py`
  запускать напрямую — это отдельная проблема не в нашей папке, чинить не
  наше дело (не наша папка).

## Классы — обоснование маппинга

См. `configs/classes.yaml` (там же комментарии). Коротко:
- `restroom -> bathroom` — прямое указание пользователя.
- `door/window/enterence -> opening` — по аналогии с тем, что combined_out
  САМ определяет opening = двери+окна; entrance — тоже дверь.
- `coridor/hall/room/stairs/storage/toilet(root)` — исключены из test GT
  (аннотации выбрасываются перед COCOeval), а не натянуто к чему-то
  приравнены. Осознанный компромисс: часть test-инстансов модель в принципе
  не может быть оценена/наказана за них, зато taxonomy остаётся честной.
  Если пользователь захочет иначе (напр. room/hall -> living) — это ОДНА
  правка в classes.yaml (`ugc_to_canonical` / `ugc_excluded_categories`),
  весь даунстрим-код таксономию не хардкодит.

## Instance-экстракция из семантических масок (train/valid)

`data_prep/coco_utils.mask_to_instances` — connected components (8-connectivity)
на бинарной маске одного класса = один instance, полигон через
`cv2.findContours` + `cv2.approxPolyDP`. Ограничения:
- пиксели ignore(255) не относятся ни к одному классу и МОГУТ разрезать один
  визуальный instance на несколько components (напр. подпись площади поверх
  комнаты) — не исправлено намеренно, задокументировано, единообразно влияет
  на все instance-модели (RF-DETR/YOLO/MaskRCNN/SAM), т.к. все они используют
  один и тот же train_coco.json/valid_coco.json.
- `min_instance_area_px=24` (px² в разрешении маски, т.е. 256x256) отсекает
  шумные компоненты растеризации — если после первого прогона окажется, что
  отсекаются реальные мелкие проёмы/окна, уменьши в classes.yaml.

## Инцидент: CUDA_VISIBLE_DEVICES не был зафиксирован (2026-07-30)

Первый реальный прогон `models/rfdetr_seg/train.py` на сервере упал с OOM на
GPU 0 (`Process ... has 25.73 GiB memory in use` — чужой процесс на shared
сервере). Причина: ни один train/infer скрипт не выставлял
`CUDA_VISIBLE_DEVICES`, поэтому PyTorch Lightning видел все 4 карты
(`CUDA_VISIBLE_DEVICES: [0,1,2,3]` в логе) и по умолчанию сел на GPU 0 —
занятую, а не на GPU 1, как было явно решено в начале задачи ("используем
только вторую видеокарту, индекс 1").

Исправлено: во ВСЕХ `models/*/train.py` и `models/*/infer_and_eval*.py`
(11 файлов) в самом начале файла, до любого импорта torch/rfdetr/ultralytics/
mmengine/segment_anything, добавлено:
```python
import os
os.environ.setdefault("CUDA_VISIBLE_DEVICES", "1")
```
`setdefault`, а не прямое присваивание — если пользователь сам явно
выставит `CUDA_VISIBLE_DEVICES` в shell перед запуском, скрипт его не
перетрёт. Порядок важен: `import torch` (и всё, что его тянет) должен идти
СТРОГО после этой строчки — иначе CUDA context уже инициализируется со
всеми видимыми картами и переменная не подействует.

Перед повторным запуском:
1. Проверить, что на GPU 1 реально есть свободная память: `nvidia-smi`.
2. `output/rfdetr_seg/checkpoints/` не пуст после упавшего прогона (лог
   предупреждал: "Checkpoint directory ... exists and is not empty") —
   решить: удалить старые файлы или передать `--resume` на нужный чекпоинт
   (флаг уже есть в `train.py`).

## Переносимость на сервер (добавлено после первого ревью)

Изначально `models/maskrcnn_mmdet/config_maskrcnn.py` хардкодил абсолютные
Windows-пути прямо в конфиге mmdet (дублируя paths.yaml) — при переезде на
сервер это два места для правки, легко забыть одно и получить рассинхрон.
Исправлено: `config_maskrcnn.py` больше не содержит путей вообще, все
датасет-специфичные поля (`data_root`, `ann_file`, `work_dir`, `metainfo`,
`num_classes`, `load_from`) подставляет `models/maskrcnn_mmdet/train.py`
программно из `load_paths()`/`load_classes()` — правится только
`configs/paths.yaml` (или env-переменные), как и для остальных 4 моделей.

Также добавлена поддержка переменных окружения `CLAUDE_COMBINED_OUT_ROOT` /
`CLAUDE_UGC_LABELED_ROOT` / `CLAUDE_PROJECT_ROOT` в `data_prep/coco_utils.py`
(`load_paths()`) — перекрывают `paths.yaml` без правки файла, удобно для
запуска на сервере/в CI без ручного редактирования конфига каждый раз.
